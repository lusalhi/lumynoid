### Platform restrictions on Accessibility

- claim: In Android 17, Advanced Protection Mode (AAPM), which users opt into, blocks the Accessibility API for apps that do not declare isAccessibilityTool="true". Existing grants are revoked automatically, and users cannot grant new ones while AAPM is on. Automation tools and assistants are explicitly listed as not qualifying. AAPM also blocks sideloading. | source: https://securityaffairs.com/189497/security/advanced-protection-mode-in-android-17-prevents-apps-from-misusing-accessibility-services.html | publisher: Security Affairs (citing Android Authority and developer.android.com/about/versions/17/features) | pub_date: 2026-03-16 | accessed: 2026-11-14 | confidence: medium (reported from Beta 2; final shipped behavior not checked against primary docs) | class: version-compat
- claim: Android 17 was released on 2026-06-16 and is available on most supported Pixels. | source: https://developer.android.com/blog/posts/android-17-is-here (title and date seen in the related-posts list on developer.android.com) | publisher: Android Developers | pub_date: 2026-06-16 | accessed: 2026-11-14 | confidence: medium | class: version-compat
- claim: Android 13 "Restricted Settings" blocks sideloaded apps that were installed through the non-session install API from getting Accessibility or Notification Listener access until the user goes to App info and taps "Allow restricted settings." Android 15 added Enhanced Confirmation Mode to close the session-installer loophole. Beta reporting says Android 16 blocks granting accessibility during active phone calls. | source: https://www.androidauthority.com/android-15-enhanced-confirmation-mode-3436697 ; https://androidauthority.com/android-16-phone-call-protections-3526068 ; https://cleanbrowsing.org/support/mobile/disable-restricted-settings-android (all via search summary) | publisher: Android Authority; CleanBrowsing | pub_date: 2024-04 to 2025-02 | accessed: 2026-11-14 | confidence: medium (older than the freshness window; final Android 16 and 17 behavior not checked) | class: version-compat

## Leads (worth chasing, not chased)
- Play Policy Center October 2025 update page (answer/16550159): the exact effective date of the autonomy ban and whether "human-in-the-loop, user-confirmed per step" agent designs count as "deterministic" or "narrow, clearly understood purpose."
- The "preview of upcoming version" link on answer/16585319, and the AppFunctions API requirements effective 2027-04-14: these may set rules for third-party agent callers.
- The EXECUTE_APP_FUNCTIONS protection level in the API reference: whether it is signature/privileged/role-only or can be granted to any third-party agent app. The overview says only "authorized apps (callers)" and that pipeline access is limited.
- The primary developer verification FAQ (developer.android.com/developer-verification): whether direct APK installs, as opposed to participating stores, are blocked in the four countries now, and how ADB installs and advanced-flow installs behave for Indonesian users.
- Final Android 17 behavior: developer.android.com/about/versions/17/features and the AAPM docs (AdvancedProtectionManager API), to confirm the accessibility block shipped as described in Beta 2.
- Android 16/17 ECM behavior for session-installed sideloads (F-Droid and Obtainium install through sessions): whether the user can still enable accessibility via "Allow restricted settings."
- Whether F-Droid or IzzyOnDroid builds signed by F-Droid, or the developer's own APK, can work with the hobbyist limited-distribution account (20-device cap) after 2027.
- Google "Connected Apps Platform" / Android intelligence system: whether a third-party app can register as the "system AI agent."
- keepandroidopen.org campaign status.
