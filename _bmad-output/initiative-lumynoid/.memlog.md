topic: Orang awam punya asisten AI pribadi di HP Android-nya sendiri
updated: 2026-11-14T11:47

- (decision) Sumber: riset-lumynoid-android-agent (2026-11-14) dan lumynoid-decisions (2026-11-14). Catatan keputusan ditulis sesudah riset dan menjawab rekomendasinya; jika berbeda (Telegram v1, Accessibility sebagai fallback, Play ditutup, fork Operit), K3/K6/K12 dan bagian Masih terbuka yang berlaku
- (direction) Bahasa dokumen initiative: Indonesia, mengikuti kedua sumber
- (requirement) R1 (Visi, K1, K7): orang awam memasang app, mengisi endpoint/API key AI miliknya, lalu mendapat jawaban chat pertama hanya lewat layar app, tanpa terminal, akun Lumynoid, VPS, atau langkah teknis lain
- (requirement) R2 (K7): pengguna menambah provider OpenAI-compatible (preset populer atau URL custom) dan Anthropic dengan API key sendiri, mengetes koneksinya dari app, dan memakai provider mana pun yang lolos tes di chat
- (requirement) R3 (K2, K9): chat di dalam app menampilkan jawaban streaming dengan markdown dan blok kode; percakapan tersimpan di daftar dan bisa dilanjutkan
- (requirement) R4 (K2, K4): agent menjalankan perintah shell di Linux userland tersembunyi, termasuk coding (menulis file, npm install, menjalankan skrip); pengguna melihat tiap perintah dan hasilnya sebagai kartu aktivitas, dan userland hanya menyala saat tool shell dipakai
- (requirement) R5 (K2): agent mencari di web dan membaca isi halaman untuk menjawab, dan pengguna bisa membuka halaman sumbernya; tanpa mengendalikan Chrome
- (requirement) R6 (K2, K6, riset Rek 2): pengguna membuat tugas terjadwal sekali atau berulang lewat chat atau layar tugas terjadwal; tugas berjalan tepat waktu saat app tertutup dan layar mati, hasilnya muncul sebagai notifikasi dan di percakapan; app memandu pengecualian optimasi baterai dan pengaturan autostart per merek HP
- (requirement) R7 (K5): pengguna memasang skill pihak ketiga berformat Agent Skills (SKILL.md) dan agent memakainya; acuan: Binance Agentic Wallet (CLI npm baw + SKILL.md, login kode pairing + konfirmasi di Binance App, transaksi contract-call preview/execute)
- (requirement) R8 (K9, K10): aksi merusak, aksi keuangan, dan pengiriman data keluar tidak berjalan sebelum pengguna menyetujui kartu konfirmasi yang dirender app; teks dari LLM tidak bisa tampil sebagai kartu konfirmasi atau aktivitas
- (requirement) R9 (K10): log aksi mencatat setiap tool call (perintah, URL, file, skill) dengan hasilnya, dan pengguna bisa membukanya dari app
- (requirement) R10 (K10): instruksi di konten web atau output tool tidak bisa memicu aksi yang butuh konfirmasi tanpa kartu konfirmasi R8
- (requirement) R11 (K9): hasil kerja agent berupa halaman web/HTML atau file bisa dipratinjau di dalam app
- (requirement) R12 (K9, K11, riset Rek 5): app hemat kuota: saat key/provider kena limit, key/provider berikutnya yang dikonfigurasi dipakai; tugas agent hanya memakai model yang mendukung tools; konteks dipangkas; sisa kuota dan status provider terlihat di app
- (constraint) C1 (Visi): open source dan gratis; tanpa server Lumynoid, inferensi lewat endpoint pengguna
- (constraint) C2 (K1): tidak ada terminal yang terlihat di UI
- (constraint) C3 (K3; riset D2 [18][19][20]): tidak mengendalikan app lain dan tidak memakai Accessibility API
- (constraint) C4 (K4; riset D3 [13][15]): harness agent native Kotlin buatan sendiri; tidak bergantung pada CLI OpenCode/Claude Code atau harness yang butuh proses terus hidup
- (constraint) C5 (K4, K6; riset D1 [1][2][7][8]): berbasis kejadian, tanpa proses always-on: exact alarm + notifikasi + FGS hanya selama ada tugas; dataSync FGS dibatasi 6 jam/24 jam (Android 15+) dan job dari FGS ikut kuota normal (Android 16)
- (constraint) C6 (K4; riset D1 [3][10]): userland proot hanya hidup saat tool shell dipakai; phantom process killer (maks 32 child process lintas app, Android 12+) dan batas memori berbasis RAM (Android 17) membatasi shell, node, git
- (constraint) C7 (riset D3 [11][4]): eksekusi binary patuh W^X untuk targetSdk 29+ (tidak mengeksekusi file dari direktori yang bisa ditulis app); build untuk Play terikat larangan unduh kode native, build GitHub/F-Droid tidak
- (constraint) C8 (K10): shell disandbox di folder app; konten web diperlakukan sebagai data
- (constraint) C9 (K9): kartu konfirmasi dan aktivitas tool dibuat oleh app dari data tool call, bukan dari teks LLM
- (constraint) C10 (K7; Anthropic legal): MVP hanya API key milik pengguna; login memakai langganan Claude dilarang untuk app pihak ketiga; tidak menjanjikan model gratis OpenCode Zen (hanya lewat OpenCode, riset [37])
- (constraint) C11 (K11; riset D4 [34][35][36][44]): dirancang untuk kuota gratis: OpenRouter tanpa kredit 50 request/hari, satu tugas sekitar 10-20 panggilan LLM; tool calling model gratis tidak andal (tool call kosong, no endpoints support tool use) dan harus ditangani
- (constraint) C12 (K8): Kotlin + Jetpack Compose, Android saja
- (constraint) C13 (K12): app baru, bukan fork Operit; Operit (LGPL-3.0) hanya referensi teknis
- (constraint) C14 (Masih terbuka; riset D2 [29][31][32]): distribusi pasti lewat GitHub Releases dan F-Droid (anti-fitur NonFreeNet); Play belum diputuskan
- (assumption) Selalu bisa dihubungi di v1 berarti: chat kapan saja saat app dibuka, dan tugas terjadwal berjalan saat app tertutup; menerima pesan masuk saat app tertutup baru datang bersama Telegram di v1.x (K6, riset ringkasan 2)
- (assumption) v1 dan MVP di catatan keputusan adalah rilis yang sama
- (assumption) Onboarding pengecualian baterai dan panduan autostart per merek (riset Rek 2) masuk v1 karena tugas terjadwal (K2) bergantung padanya
- (assumption) Model lokal (routing intent, riset Rek 5) tidak masuk v1; catatan keputusan tidak menyebutnya
- (assumption) Uji daya tahan tugas terjadwal: 7 hari berturut-turut di satu HP Xiaomi dan satu Samsung (riset: daya tahan di Xiaomi/Samsung harus diuji sendiri; angka 7 hari usulan PO)
- (question) Distribusi Play: apakah FGS untuk tugas agent dan shell (binary dibundel + npm install saat runtime) lolos kebijakan Play [4][5][11]? Menunggu: epic distribusi dan architecture
- (question) Verifikasi developer 2027: akun penuh ($25 + identitas) atau advanced flow; jalur open-source registry dan APK bertanda tangan F-Droid [28][29][30]. Harus diputuskan sebelum rollout global 2027
- (question) Layanan pencarian web untuk tool cari (gratis atau murah) belum diriset. Menunggu: R5
- (question) Ukuran userland, strategi unduhnya, dan batas npm install di HP sungguhan (phantom process killer, memori Android 17) [3][10]. Menunggu: R4, R7
- (question) Library agent Kotlin/JVM (Koog, LangChain4j, atau buatan sendiri) belum dievaluasi. Menunggu: architecture
- (question) Model gratis mana yang andal untuk tool calling? Belum ada benchmark; perlu uji sendiri. Angka free tier Groq/Gemini hanya terlihat di console [38][61]. Menunggu: R12, preset provider di R2
- (question) Apakah app BYOK gratis wajib terdaftar sebagai PSE Komdigi? (lead riset yang belum dikejar)
- (question) Lisensi open source Lumynoid sendiri belum dipilih
- (question) Aturan inklusi F-Droid (tanpa library non-free) belum dicek terhadap pilihan dependensi
- (question) Penyimpanan API key dan riwayat chat: apakah semua tetap di HP, terenkripsi, dan bisa dibackup? Sumber tidak menyebutnya
- (question) Bahasa UI v1 (Indonesia, Inggris, atau keduanya) dan versi Android minimum belum ditetapkan
- (question) Kebijakan REQUEST_IGNORE_BATTERY_OPTIMIZATIONS dan angka konsumsi baterai belum ditemukan. Menunggu: R6
- (note) Pasca-MVP, bukan v1: Telegram (K6), GenUI/A2UI dengan fallback teks (K9), Sign in with ChatGPT via Responses API (K7, kelayakan Android belum dipastikan)

- (event) Self-validate pass 2 (preservation): tidak dibawa karena tidak relevan untuk v1 atau digantikan keputusan: kontrol bertingkat Accessibility/Shizuku (riset Rek 3, diganti K3), AAPM Android 17 dan restricted settings Android 13 (hanya relevan bila Accessibility dipakai), distribusi di luar Play (riset Rek 1, digantikan C14), Telegram v1 (riset Rek 2, diganti K6), fork-atau-baru (riset Rek 6, diputus K12); Chaquopy dan WebView+evaluateJavascript adalah HOW untuk architecture; peta pesaing D5 adalah posisi, bukan syarat build

- (decision) Pencarian web v1: DuckDuckGo HTML sebagai backend default keyless (keputusan user 2026-11-14, setelah membandingkan SearXNG, Marginalia, Wikipedia, Brave, Tavily); rapuh (bot challenge), SearchPort membuat penggantian murah (spine). Menutup open question layanan pencarian

- (decision) Dependensi F-Droid: stack spine sudah dicek lolos Inclusion Policy; dependensi baru dicek per PR (spine AD-17). Menutup open question aturan inklusi F-Droid
- (decision) Penyimpanan: API key dienkripsi AES-GCM dengan kunci Keystore non-exportable, terpisah dari Room (AD-15); semua data tetap di HP, dikecualikan dari backup awan dan transfer antarperangkat (AD-25). Yang tersisa: retensi dan ekspor riwayat chat
