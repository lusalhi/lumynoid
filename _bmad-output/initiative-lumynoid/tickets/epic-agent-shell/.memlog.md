topic: Agent mengerjakan tugas coding di HP
updated: 2026-11-21T08:52
---


- (requirement) R1 (parent R4): Agent menjalankan perintah coding di Linux userland tersembunyi: menulis file, memasang paket npm, dan menjalankan skrip. Pengguna melihat perintah dan hasil lewat kartu aktivitas; userland hanya aktif saat dipakai untuk tugas shell.
- (requirement) R2 (parent R8): Aksi merusak, keuangan, dan pengiriman data keluar tidak berjalan tanpa persetujuan pengguna di kartu buatan app untuk panggilan itu. Teks LLM tidak dapat membuat kartu aktivitas atau kartu konfirmasi.
- (requirement) R3 (parent R9): Pengguna bisa membuka log aksi yang memuat setiap panggilan tool beserta target dan hasilnya.
- (requirement) R4 (parent R10): Instruksi dari output tool tidak dapat memicu aksi yang butuh persetujuan tanpa kartu konfirmasi. Bukti untuk konten halaman web menjadi bagian epic Browsing Web.
- (requirement) R5 (parent R11): Pengguna bisa membuka pratinjau file dan halaman HTML hasil kerja agent di dalam app.
- (constraint) C1 (parent C2, C4, C5, C6): Tidak ada terminal di UI atau proses always-on. Satu tugas berjalan lewat TaskRunner dan AgentService yang sudah ada. Menunggu persetujuan tidak memegang slot, userland, atau foreground service bila tidak ada kerja lain (AD-2, AD-3, AD-22).
- (constraint) C2 (parent C7, C8; AD-14, AD-15, AD-20): Target tetap SDK 37. Workspace dan rootfs bukan akses ke data privat app, secret, atau workspace lain. Rute egress dan batas akses dibuktikan di perangkat sebelum shell diaktifkan; persetujuan egress bukan pengganti isolasi filesystem.
- (constraint) C3 (parent C9, C11; AD-7, AD-8, AD-10, AD-26): Hanya panggilan tool terstruktur melewati gerbang. Event bertipe menjadi sumber kartu dan log. Runner menegakkan batas panggilan LLM dan satu percobaan perbaikan tool call; rotasi kuota tetap di epic Hemat Kuota.
- (question) Distro, ukuran unduhan, commit proot/loader, dan batas filesystem, jaringan, serta proses mana yang lolos pada HP arm64 API 37 dengan APK target SDK 37? Jawab di spike 2.1 dengan hasil ukur dan keputusan lanjut atau ubah desain (AD-14, AD-17, AD-20).
- (decision) 2026-11-21. Pengguna menyetujui replan Epic 2. Gunakan satu APK dengan PRoot dan folder proyek biasa yang dikelola aplikasi. Bukti Spike 2.1 di Samsung SM-S731B API 37 menunjukkan tulis/baca, npm offline, skrip Node, serta cleanup lulus. Rilis awal memakai operasi coding yang ditentukan aplikasi dan paket lokal terpilih. Shell bebas dan eksekusi kode pihak ketiga ditunda sampai batas data privat dan jaringan terbukti.
- (requirement) R1 (parent R4): Agent menulis file proyek, memasang paket lokal yang disediakan aplikasi, dan menjalankan skrip bawaan aplikasi melalui alat coding terstruktur di Linux userland. Pengguna melihat setiap aksi dan hasilnya di kartu aktivitas.
- (constraint) C2 (parent C7, C8; AD-14, AD-15, AD-20): Satu APK target SDK 37 memakai PRoot dengan folder proyek biasa. Aplikasi memvalidasi akses file dan menentukan setiap operasi runtime. Instalasi npm berjalan offline dengan lifecycle scripts dimatikan. Kode yang dieksekusi berasal dari aplikasi dan dependensinya yang sudah ditinjau serta terverifikasi.
- (note) Eksperimen runtime 2.1 lulus untuk cakupan awal. Hasil pengujian isolasi shell umum tetap tercatat di Spike 2.1. AD-14/AD-20 perlu diselaraskan dengan ruang lingkup ini dan tetap menjadi acuan lifecycle serta batas ekspansi ke shell dan skill.
- (event) Self-validate coherence: ID R1–R5 dan C1–C3 tetap. Scope, syarat perangkat, gate lifecycle, dan dependensi 2.5 hingga 2.12 konsisten untuk rilis awal.
- (event) Self-validate preservation: hasil Samsung, riwayat 2.1, persetujuan, log, preview, dan kontrak untuk epic berikutnya tetap dirujuk. Validasi set dan dependency menunjukkan 2.5 siap, dengan status 2.1 untuk shell umum tetap tercatat.
- (decision) 2026-11-23. Berdasarkan laporan uji v0.4.1, pemilik memilih balasan alternatif otomatis setelah Decline, satu balasan teks tanpa tool; Stop tetap membatalkan. Jadwalkan sebagai follow-up Epic 2 sebelum Epic 3, tanpa membuka ulang Projects 8.8.
- (requirement) R6 (parent R8): Setelah pengguna menolak aksi lewat kartu, agent menawarkan alternatif lewat satu balasan teks di chat tanpa menjalankan aksi itu atau tool lain. Penolakan tetap terlihat di log; Stop tetap berarti berhenti.
- (event) Self-validate coherence: R6, Story 2.13, dan syarat Epic 3 konsisten; validasi tree tidak menemukan konflik atau dependensi yang hilang.
- (event) Self-validate preservation: aturan persetujuan, bukti rilis lama, dan penerimaan Projects 8.8 tetap utuh. Tidak ada story lama yang ditulis ulang.
