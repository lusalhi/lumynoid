- `app/src/main/kotlin/dev/lusalhi/lumynoid/app/MainActivity.kt:51–83` — A crash on a fresh install cannot be exported on relaunch. - `app/src/main/kotlin/dev/lusalhi/lumynoid/app/CrashReport.kt:24–38, 89` — Removing exception messages does not make the report safe to share. The formatter writes the mutable thread name verbatim and interpolates each `StackTraceElement`, including its caller-supplied filename. `CrashReportTest.kt:51–56` already demonstrates that a throwable can supply synthetic frames. A key or prompt in either field is written unchanged.
- `app/src/main/kotlin/dev/lusalhi/lumynoid/app/CrashHandler.kt:13–22` — Sanitization applies only to the exported file, not to the architecture’s release-logcat rule. Android’s [`RuntimeInit`](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/main/core/java/com/android/internal/os/RuntimeInit.java) logs the original throwable to the crash buffer through a pre-handler before this replacement default handler runs. If a release exception contains a key or prompt in its message, it still reaches logcat.
- `app/src/main/AndroidManifest.xml:27–34` — The manifest registers `androidx.core.content.FileProvider` directly. [AndroidX documents that using the base class directly can crash on some devices](https://developer.android.com/reference/androidx/core/content/FileProvider). That can prevent startup rather than just fail Share; the recorder is installed later, in `LumynoidApp.onCreate()`.
- `app/src/main/kotlin/dev/lusalhi/lumynoid/app/CrashReport.kt:68–74` — `writeText()` writes directly to the final filename, so a failed write leaves a partial report that `newest()` offers on relaunch. Write to a temporary name and rename it into place.
- `app/src/main/kotlin/dev/lusalhi/lumynoid/app/CrashReport.kt:53–65` — Filenames use locale-sensitive decimal formatting, but retention and Share sort them as strings. After switching from a locale that uses Arabic-Indic digits to one that uses ASCII digits, older reports can sort ahead of a newer one. Share then picks the wrong report, and retention can delete the newest one.
- `app/src/main/kotlin/dev/lusalhi/lumynoid/app/CrashReport.kt:56, 67–75`; `app/src/main/kotlin/dev/lusalhi/lumynoid/app/MainActivity.kt:80–83` — Cleanup ignores `File.delete()` failures. The previous handler runs outside the `try`/`catch`, so an exception from it escapes. The handler tests cover a failing write, a failing environment lookup, and a missing delegate, but not a throwing delegate.
