- `app/src/main/AndroidManifest.xml:27–34` — The manifest registers `androidx.core.content.FileProvider` directly. The [AndroidX reference](https://developer.android.com/reference/androidx/core/content/FileProvider) explicitly warns that using the base class instead of a subclass causes crashes on some devices. This can block launch before `LumynoidApp.onCreate()` installs the crash handler. Valid authority and path settings do not address that compatibility issue.
- `app/src/main/kotlin/dev/lusalhi/lumynoid/app/CrashReport.kt:68–88` — A failed write can leave an empty or truncated file that the app offers as the newest report. `writeText()` opens the final `crash-*.txt` path directly, the handler catches the failure without removing the file, and `newest()` checks only the filename. The existing failure test blocks directory creation, so it never exercises a failure after the file is opened.
- `app/src/main/kotlin/dev/lusalhi/lumynoid/app/CrashReport.kt:68–88` — Setting the device clock back can hide or immediately delete the crash that just happened. `CrashHandler.install()` supplies `System.currentTimeMillis()`, and both `newest()` and pruning sort by that timestamp in the filename. If five existing reports have later timestamps, pruning deletes the just-written report.
- `app/src/main/kotlin/dev/lusalhi/lumynoid/app/MainActivity.kt:72–75` — Dismiss hides the banner without ensuring all local reports are deleted. `CrashStore.clear()` ignores `File.delete()` failures, so a surviving original can bring the banner back on relaunch. Dismiss also never removes the `cacheDir/export/` copy created before the chooser opens, even if the user canceled sharing.
- `app/src/main/kotlin/dev/lusalhi/lumynoid/app/Screens.kt:191–211` — Share and Dismiss can become unreachable in a short window with large accessibility text. The non-scrollable banner measures its title and body before the action row, which can be left with no height. `MainActivity.kt:61–84` gives the current screen only the space left over after the banner, so the banner can also crowd out provider setup.
- `app/src/main/kotlin/dev/lusalhi/lumynoid/app/CrashReport.kt:107–114` — The handler does not enforce the plan’s “never throws” rule when the previous handler throws. The delegation is outside the `try`, and `CrashHandler.install()` captures whatever default handler is registered. The JVM tests cover a successful callback and a null callback, not a throwing one.
- `app/src/test/kotlin/dev/lusalhi/lumynoid/app/CrashReportTest.kt:110–132,171–179` — The tests do not cover every I/O matrix row as required. They exercise `newest()`, `clear()`, and a successful `copyForExport()`, but not the first-run banner, chooser handoff, or banner retention after a failed copy. The manifest test also checks `grantUriPermissions` with `assertNotNull(getAttribute(...))`; DOM returns an empty string for a missing attribute, so the assertion passes if the grant is missing or set to `"false"`.
